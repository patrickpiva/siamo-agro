[01 · Objetivo]

Objetivo

Validar, de ponta a ponta, os fluxos críticos de negócio da plataforma AgraIA antes de cada release de produção, garantindo que autenticação, criação de anúncios, matchmaking, transações e reputação funcionem conforme o esperado da perspectiva do usuário final.

[04 · Cenários de Teste]

Cenários de Teste

01 Autenticação

Confirmar que o usuário consegue entrar com WhatsApp.

Passo Ação Resultado esperado
1.1 Acessar /entrar Tela "Entre com seu WhatsApp" exibida
1.2 Digitar 11999990001 e tocar em "Receber código" Redireciona para tela de código
1.3 Digitar 123456 Login efetuado, redireciona para /feed
1.4 Recarregar a página Sessão mantida (não volta ao login)
✓ Aprovado se: o feed carrega com a saudação personalizada.
02 Onboarding (novo usuário)

Validar o cadastro completo de um perfil novo.

Passo Ação Resultado esperado
2.1 Entrar com a conta reserva (sem perfil) Redireciona para /cadastro/perfil
2.2 Selecionar tipo (Produtor / Prestador) Avança para dados pessoais
2.3 Preencher nome, propriedade e bio Avança para localização
2.4 Permitir GPS ou informar CEP Cidade/estado preenchidos automaticamente
2.5 Enviar foto de perfil Upload concluído, prévia exibida
2.6 Aceitar consentimento LGPD Perfil criado, tela "Pronto" exibida
✓ Aprovado se: o perfil é criado e o usuário chega ao feed.
03 Criação de anúncio

Validar o assistente de publicação.

Passo Ação Resultado esperado
3.1 No feed, tocar em "Publicar" Abre /anuncio/novo (passo 1 de 4)
3.2 Escolher o tipo (Oferta/Demanda/Serviço/Equipamento) Avança para detalhes
3.3 Preencher categoria, título, preço e descrição Avança para mídia
3.4 Adicionar foto (opcional) e revisar Tela de revisão correta
3.5 Confirmar publicação Redireciona para o anúncio criado
3.6 Verificar miniatura padrão (sem foto) Ícone da categoria + cor exibidos
✓ Aprovado se: o anúncio aparece publicado e visível no feed.
04 Matchmaking

Confirmar que matches são gerados e exibidos.

Passo Ação Resultado esperado
4.1 Acessar o feed, aba "Matches para mim" Lista de matches ou spinner de cálculo
4.2 Aguardar processamento (primeira visita) Matches aparecem com % de compatibilidade
4.3 Verificar distância e selo de reputação no card Dados coerentes exibidos
✓ Aprovado se: ao menos um match é exibido com pontuação entre 0–100%.
05 Ciclo de transação

Validar a negociação completa entre dois usuários.

Passo Ação (usuário) Resultado esperado
5.1 Usuário A faz proposta em anúncio de B Transação criada com status "Proposta"
5.2 Usuário B abre a transação e troca mensagens Chat funcional em tempo real
5.3 Usuário B aceita a proposta Status muda para "Em andamento"
5.4 Ambos confirmam conclusão Status muda para "Concluído"
5.5 Cada um avalia o outro Avaliação registrada (nota + comentário)
✓ Aprovado se: o status evolui corretamente e as avaliações afetam a reputação.
06 Salvar anúncio e notificações

Validar recursos de engajamento.

Passo Ação Resultado esperado
6.1 Salvar um anúncio (ícone marcador) Confirmação visual imediata
6.2 Abrir feed, aba "Salvos" Anúncio salvo aparece na lista
6.3 Abrir /notificacoes Notificações agrupadas por dia
✓ Aprovado se: o anúncio salvo persiste e as notificações carregam.
07 Perfil e configurações

Validar gestão de conta.

Passo Ação Resultado esperado
7.1 Acessar /meu-perfil Perfil próprio com reputação e anúncios
7.2 Editar perfil (nome, foto, bio) Alterações salvas e refletidas
7.3 Acessar /configuracoes Grupos de ajustes exibidos
✓ Aprovado se: as alterações de perfil são persistidas.
08 Experiência mobile e offline

Validar a sensação de aplicativo nativo.

Passo Ação Resultado esperado
8.1 Tocar em qualquer campo de texto (iOS) Página não aplica zoom
8.2 Navegar entre páginas Skeleton de carregamento exibido (sem tela em branco)
8.3 Adicionar à tela inicial e abrir Splash exibido apenas na 1ª abertura
8.4 Ativar modo avião e navegar Banner offline + conteúdo em cache
✓ Aprovado se: não há zoom indesejado, há feedback de carregamento e o offline degrada com elegância.

Critérios de Aceitação

Severidade Definição Ação
CRÍTICO Bloqueia fluxo de negócio (login, transação) Bloqueia o release
MÉDIO Funciona com contorno Avaliar caso a caso
BAIXO Cosmético Backlog
Release aprovado quando: 100% dos cenários críticos (01, 03, 04, 05) passam e não há defeitos CRÍTICOS abertos.
